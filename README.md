# Проект
## "Защита OTP-кодом от Promo IT"

### О проекте
Мы планируем разработать простое и удобное backend-приложение, которое поможет защитить операции с помощью временных кодов. Основная цель сервиса — обеспечить безопасность при выполнении различных действий, требующих подтверждения.

#### Что будет делать сервис?

Создавать операции на защиту — пользователи смогут инициировать защиту своих операций, чтобы добавить дополнительный уровень безопасности.

Генерировать защитный код — для каждой операции будет автоматически создаваться уникальный код, который будет использоваться для подтверждения.

Отправлять код — пользователи смогут получать защитные коды через разные каналы:

* SMS — вам предстоит использовать эмулятор для отправки SMS, чтобы протестировать функционал.
* Email — коды можно будет отправлять как на эмулятор, так и на реальные почтовые адреса.
* Telegram — с помощью Telegram API вы создадите бота, который будет отправлять коды пользователям.
Проверять код — при выполнении операции пользователи смогут вводить полученный код, который будет проверяться на правильность.

Настраивать время жизни и длину кода — каждый код будет иметь ограниченное время действия. Администратор сможет настраивать, как долго код будет действовать и сколько цифр он будет содержать.

Вдохновение для проекта можно взять из концепции TOTP (Time-based One-Time Password), что поможет сделать защиту более надежной.

Таким образом, вы создадите удобный сервис, который поможет пользователям безопасно выполнять операции, используя временные коды для подтверждения.

## Реализация

Сервис OTP-кодов реализован с использованием Spring Boot, в качестве СУБД используется PostgreSQL 17 в Docker контейнере.
Для проверки работы рассылки сообщений с кодами используется заглушка SMTP-сервера в Docker контейнере, 
заглушка SMPP-сервера в Docker контейнере, взаимодействие с Telegram API выполняется по HTTP, тут нужен будет идентификатор бота.
Для авторизации используется JWT, каждый запрос должен содержать токен JWT
Для удобства вся сборка запускается при помощи docker-compose, поднимается группа Docker-контейнеров, 
настроено взаимодействие между контейнерами. Контейнер с приложением содержит этап сборки Maven, таким образом, для  
запуска приложения достаточно выполнить команду ``docker-compose up --build -d``
После запуска docker-compose доступны
 * swagger http://localhost:8080/swagger-ui/index.html#/ для просмотра описания API
 * actuator http://localhost:8080/actuator для просмотра статуса приложения
 * pgadmin http://localhost:5050/browser/ база данных ``exam_db`` логин ``admin`` пароль ``admin``
 * MailCatcher http://localhost:1080/ для просмотра Email
 * SMPPSim http://localhost:8884/ для просмотра статистики по SMS

## Логика работы

Приложение выполняет следующие основные функции:
1) При старте подключается к БД и добавляет первого администратора (если нету), а также конфигурацию по умолчанию (если нету)
2) Запускается планировщик и выполняет задачу ``otp.simple.project.backend.service.OtpCodeService.checkExpiringCode`` по крону каждую минуту
3) Для взаимодействия с приложением сначала нужно зарегистрировать пользователя и получить JWT-токен, который нужно положить в хидер каждого запроса
4) Если JWT-токен протух нужно авторизоваться заново и получить новый
5) Для выполнения многоих запросов нужны права администратора, в начале есть только один администратор, и только администратор может дать права администратора другому пользователю
6) Пользователь может получить OTP-код для операции, код отправляется пользователю и в БД хранится в зашифрованном виде, таким образом сам код может увидеть только пользователь его сделавший
7) OTP-код можно активировать пока он не протух, для активации нужен сам код и идентификатор операции

### Основные пакеты и классы приложения

 * ``otp.simple.project.backend.configuration`` тут находятся классы конфигурации
 * ``otp.simple.project.backend.domain.dto`` тут находятся DTO для передачи данных через API
 * ``otp.simple.project.backend.domain.model`` тут находятся entity-объекты для взаимодействия с БД при помощи ORM
 * ``otp.simple.project.backend.exception.LogicException`` это исключение, которое выбрасывается при какой-либо логической ошибке
 * ``otp.simple.project.backend.repository`` тут находится слой DAO: JPA-репозитории для выборки и изменения данных в БД
 * ``otp.simple.project.backend.service`` тут находится слой сервисов, сервисы обеспечивают логику роботы с данными, 
   предоставляют методы для обработки данных и используют JPA-репозитории для взаимодействия с БД
 * ``otp.simple.project.backend.service.notification`` тут расположены классы-нотификаторы, для рассылки уведомлений через Email, Sms и Telegram
 * ``otp.simple.project.backend.rest`` тут расположен слой REST-контроллеров, классы предоставляют методы REST API и вызывают методы сервисов 
 * ``otp.simple.project.backend.SpringDataApplication`` - класс запуска Spring Boot приложения
 * ``src/main/resources/application.yaml`` - конфигурационный файл приложения
 * ``backend.Dockerfile`` описание контейнера приложения, описаны две фазы:
   * ``build`` - выполняется сборка приложения Maven
   * ``run`` - выполняется запуск собранного на предыдущей фазе приложения
 * ``smpp.Dockerfile`` описание контейнера для запуска заглушки SMPP-сервера
 * ``docker-compose.yml`` файл запуска docker-compose с группой контейнеров

### Методы REST API

 * /auth/sign/up Регистрация пользователя - метод регистрирует простого пользователя и возвращает JWT токен
 * /auth/sign/in Авторизация пользователя - метод возвращает JWT токен
 * /auth/password/change Смена пароля пользователя (нужен JWT токен)
 * /user/edit Редактирование имени пользователя (нужен JWT токен)
 * /user/all Список всех пользователей, кроме администраторов (нужен JWT токен и права администратора)
 * /user/{id}/set-admin Добавить роль ADMIN пользователю (нужен JWT токен и права администратора)
 * /user/{id}/delete Удаление пользователя (нужен JWT токен и права администратора), себя удалить нельзя
 * /otp/configuration/update Изменение конфигурации (нужен JWT токен и права администратора)
 * /otp/configuration/get Получение конфигурации (нужен JWT токен и права администратора)
 * /otp/create Создание OTP-кода для операции, переданной в теле запроса (нужен JWT токен)
 * /otp/{id}/get Информация OTP-кода (нужен JWT токен, для просмотра кода другого пользователя нужны права администратора)
 * /otp/{id}/activate Активация OTP-кода по коду операции (нужен JWT токен, активировать можно только свой код)
 * /otp/all Список всех OTP-кодов (нужен JWT токен и права администратора)
 * /otp/{id}/delete Удаление OTP-кода по коду операции (нужен JWT токен и права администратора)
